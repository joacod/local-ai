# MacBook Pro M4 — 48 GB

Reference starting profile for `oMLX`.

> **Status:** starting configuration, not a completed benchmark report. Do not
> call a value tested until the run records the exact hardware, macOS version,
> `oMLX` version, model revision, quantization, context, cache state, and
> concurrency.

## Hardware

- MacBook Pro — Apple M4
- 48 GB unified memory
- Local server: `127.0.0.1:8000`

## Starting settings

| Setting | Starting value | Classification |
| --- | --- | --- |
| Models loaded | One | Recommendation |
| Active requests | `1` | Recommendation for one interactive agent |
| Memory guard | `balanced` | Upstream default |
| Context target | 32k tokens | Conservative target; measure before increasing |
| oMLX paged cache | Off for the cold lane; dedicated SSD directory for the warm lane | Tuning variable |

A context target is not a promise that every model or workload fits. Model
weights, activations, KV state, macOS, and other applications all consume the
same unified-memory pool.

## Cold baseline

Use the model directory that the main [oMLX guide](../README.md) describes:

```sh
omlx serve \
  --model-dir "$HOME/.omlx/models" \
  --host 127.0.0.1 \
  --port 8000 \
  --memory-guard balanced \
  --max-concurrent-requests 1 \
  --no-cache
```

Configure the model's context target in the oMLX settings before testing it.
Keep the first run to one request and verify `/health`, `/v1/models`, and one
chat completion before changing another setting.

## Cached tuning lane

Use a dedicated cache directory and label every result as warm or
SSD-restored:

```sh
omlx serve \
  --model-dir "$HOME/.omlx/models" \
  --host 127.0.0.1 \
  --port 8000 \
  --memory-guard balanced \
  --max-concurrent-requests 1 \
  --paged-ssd-cache-dir "$HOME/.omlx/cache"
```

Clear the hot or SSD tier with the [cache reset procedure](../README.md#reset-the-runtime-cache)
before a cold row. `--no-cache` disables oMLX's paged SSD cache; it does not
remove the model or eliminate the runtime's internal KV state.

## Tune one variable at a time

- Try a larger context only after the baseline has stable memory pressure.
- Test `--max-concurrent-requests 2` or `4` in a separate throughput lane.
- Compare cache-off, hot-cache, and SSD-restored rows separately.
- Stop when memory pressure, swap, or model-load failures become persistent.

The result of a change belongs in the runtime configuration tuning guide or a
current runtime experiment note, not in this hardware profile as an unlabeled
claim.
