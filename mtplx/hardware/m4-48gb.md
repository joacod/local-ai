# MacBook Pro M4 Max — 48 GB

Reference starting profile for MTPLX.

> **Status:** starting configuration, not a completed benchmark report. Do not
> call a value tested until the run records the exact hardware, macOS version,
> MTPLX version, model revision, quantization, context, serving mode, and
> concurrency.

## Hardware

- MacBook Pro — Apple M4 Max
- 48 GB unified memory
- Local server: `127.0.0.1:8000`

## Starting settings

| Setting | Starting value | Classification |
| --- | --- | --- |
| Model | One complete checkpoint with matching MTP weights | Compatibility requirement |
| Active requests | `1` | Recommendation for one interactive agent |
| Generation mode | Native MTP | Default operational lane |
| Context | Start conservatively within the model's supported limit | Recommendation; measure before increasing |
| Session cache | Clear between cold rows; keep warm rows separate | Tuning variable |
| Fan control | Leave optional thermal controls unchanged initially | Conservative default |

A model's file size is not a runtime-memory guarantee. Leave headroom for the
model runtime, KV/session state, macOS, and other applications.

## Select, inspect, and start

Use the model-selection commands from the main [MTPLX guide](../README.md),
then choose the downloaded model with `mtplx start`:

```sh
MODEL='<complete-mtplx-model-or-repository>'
mtplx pull "$MODEL"
mtplx inspect "$MODEL" --json
mtplx start
```

For an API-only foreground server after the model is selected/configured:

```sh
mtplx serve \
  --host 127.0.0.1 \
  --port 8000 \
  --no-stats-footer
```

Verify `/health` before recording a row. Confirm `load_mtp`, `mtp_enabled`,
`depth`, and `generation_mode` rather than inferring MTP from a model name.

## Cold and mode tuning

Clear the runtime session cache between cold rows without deleting model files:

```sh
curl -X POST http://127.0.0.1:8000/admin/cache/clear
```

Compare target-only AR only as a separate lane:

```sh
mtplx serve --host 127.0.0.1 --port 8000 --no-mtp
```

Keep MTP and AR results separate. For draft-depth tuning, use MTPLX's hardware
measurement command and record the resulting depth rather than assuming that a
depth that wins on another Mac will win here:

```sh
MODEL='<complete-mtplx-model-or-repository>'
mtplx tune --model "$MODEL" --retune
```

## Record a tested value

Include the chip and memory, macOS, MTPLX version, exact model repository and
revision, quantization, context, MTP/AR mode, depth, cache state, concurrency,
`ttft_s`, prefill/decode rates, peak memory, and `accepted_by_depth` /
`drafted_by_depth`. Put the resulting row in the [shared runtime tuning and
qualification guide](../../docs/tuning.md) or a current runtime experiment
note; keep this file as the latest machine profile. This repository does not
yet have a reusable MTPLX qualification command.
